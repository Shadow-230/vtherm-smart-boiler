# VTherm Smart Boiler — code review (commit `16f0448`, 2026-09-24)

> Read-only review: neither the code nor the specification was changed. This is the English
> translation of the report. The Polish original and the full data are in the git-ignored
> `research/2026-09-24-code-review/` (in Polish): all 293 findings with scenarios, evidence and the
> verifiers' verdicts (`findings.md`), 389 requirements with sources (`requirements.md`), the
> requirement → code → test matrix of 361 rows (`matrix.md`), 363 proposed tests
> (`missing-tests.md`) and the raw results (`data.json`). Coverage report:
> `.tmp/review-cov/pytest.txt` (git-ignored).

The plugin has a very good architecture and high test coverage (95 %), but it is **not ready to be
connected to a real boiler**. Handing control back has two critical gaps, and the demand and
anti-cycling logic has several serious ones. Release validation (hassfest, HACS) does not pass today.

## 2. Summary and rating

**Strengths:**
- `core/` consists of pure functions on frozen dataclasses, with a test that keeps it free of HA.
- The controller has an explicit, documented order of precedence, and every decision carries its
  reasons.
- Write guards are separate from decisions. Hand-back bypasses the guards, runs in a shutdown job,
  and a failed one is retried.
- The DHW-enable bit is never written. A CS value between 1 and 7 °C is refused.
- The feature-manager contract matches vtherm_api 0.5.0 and VT 10.4.0.
- Translations have a key-parity test; coverage is high.

**Weaknesses:**
1. **Hand-back is not reliable in real failures:**
   - the target entity unavailable at the moment of hand-back,
   - the OTGW CH=0 flag surviving CS=0,
   - no hand-back after a Home Assistant crash,
   - hand-back skipped after a write that timed out.
2. **Translating VT's model into boiler demand has gaps:** `unavailable` zones and over_climate
   zones in "auto" count as no demand, and the comfort correction can get stuck.
3. **Anti-cycling acts only at the decision clock** and collides with the switching budget and the
   daily write cap.
4. **Release:** hassfest will not pass, and the monitor's verdict is practically unreachable.
5. **Tests reach 95 % coverage**, but some closed-loop tests pass for the wrong reasons. A restart
   with stored state and the passage of time are almost untested.

**Climate entity:** the plugin has none and by design should not (SCOPE §1). The checklist items
`supported_features`, `hvac_modes`, `preset_modes` and `min/max/step` do not apply. Their
counterparts are the ranges of the number selectors and unit handling (P11, P51).

## 7. The five changes to make first

1. **Reliable hand-back (P01, P02, P04, P05, P06, P28).**
   - Check the target's availability and confirm the hand-back by read-back.
   - For OTGW, send CH=1 before CS=0.
   - Store a persistent "controlling" marker in case Home Assistant crashes.
   - Set `_wrote_since_hand_back` before every write attempt.
   - Refuse "No control" while a hand-back is pending.
2. **Correct demand from VT (P03, P12, P13, P19, P14).**
   - `unavailable` zones mean "unknown", not "no demand".
   - The auto and heat_cool modes can heat.
   - An over_climate zone does not stop the correction from falling.
   - Validate `count_threshold`.
   - Define which zones count for frost.
3. **Anti-cycling on flame edges, consistent with the budgets (P08, P09, P20, P21).**
   - Decide at K4 what the minimum pause applies to.
   - The switching budget must not hold OFF.
   - A burn of unknown kind does not hold heating.
   - Change the tests that entrench the defects today (P58).
4. **Freshness, read-back and units (P10, P07, P11, P22, P23, P43, P26).**
   - A freshness-limit field in the UI and one freshness rule.
   - Fix the rewrite guard.
   - Convert °C/°F.
   - Use the CH echo and show the confirmed value.
5. **Release validation and the monitor (P18, K1, P54, P17, P30, P56).**
   - Fix `en.json`/`pl.json` and the manifest (documentation, issue_tracker, codeowners).
   - Add `hacs.json` with `homeassistant: 2026.3.0`, README, LICENSE, `brand/`.
   - Make the verdict reachable despite short data gaps.
   - Remove blocking I/O from the event loop.
   - Add tests for restart, the passage of time and the J4 scenarios.
